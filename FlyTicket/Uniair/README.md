# 立榮航空班機空位抓取（第一部分：搜尋頁輸入）

用 Playwright 自動開啟立榮搜尋頁，填入啟程地/目的地/出發日期/搭乘人數，
以截圖 + 視覺模型辨識驗證碼，確認輸入完整後按下「搜尋」。

## 重要：立榮一律「有視窗」執行，不要加 `--headless`
立榮站台會把無頭瀏覽器（headless）視為攻擊直接擋掉，驗證碼頁與搜尋頁都會失敗。
本目錄所有腳本（`uniair-search.js` / `uniair-fares.js` / `uniair-route-fares.js`）
**都請用預設的有視窗模式執行**，需要背景跑時請用虛擬桌面/遠端桌面保持工作階段，不要加 `--headless`。

## 安裝
```powershell
npm install
npx playwright install chromium
```

## 模型端點（驗證碼辨識）
所有模型設定都放在 `.env`，程式統一從 `.env` 讀取（用 dotenv 載入）：
`
CAPTCHA_BASE_URL=http://svc.summer-blue.com:8189/v1
CAPTCHA_API_KEY=llamacpp
CAPTCHA_MODEL=swift-1.5-iq3_xxs
CAPTCHA_TIMEOUT_MS=60000
CAPTCHA_RETRIES=3
CAPTCHA_MAX_TOKENS=1024
`
要換端點/金鑰/模型，直接改 `.env` 即可，不必動程式碼。
## 執行
```powershell
node uniair-search.js --dep 松山 --arr 金門 --date 2026-10-25 --pax 2
```
選項：
- `--dep` / `--arr`：航點名稱或 IATA 碼（松山/TSA、台中/RMQ、嘉義/CYI、台南/TNN、
  高雄/KHH、花蓮/HUN、台東/TTT、金門/KNH、澎湖/MZG、南竿/LZN、北竿/MFK）
- `--date`：出發日期，接受 `2026-10-25` / `2026/10/25` / `20261025`
- `--pax`：成人旅客人數（嬰兒預設 0）
- `--headless`：不開視窗
- `--keep-open`：跑完保持瀏覽器開啟（除錯用）
- `--captcha 483021`：手動指定驗證碼，跳過模型（端點不通時測試用）

執行後產出：
- `captcha.png`：送模型辨識的驗證碼截圖
- `after-search.png`：按下搜尋後的整頁截圖

## 驗證碼流程
BotDetect 驗證碼每次提交後會刷新，因此腳本截圖「當下」的驗證碼圖片元素
（`#...logincaptcha_CaptchaImage`），轉 base64 送視覺模型讀取 6 碼，再填入
`#CPH_Body_txt_CaptchaCode`。辨識失敗會重試（`CAPTCHA_RETRIES`，預設 3 次）。



## 第二部分：抓取航班資訊存 JSON
進入航班頁（`ubk_select-itinerary.aspx`）後，抓取「該日」航班清單，每筆含：
出發地點、抵達地點、日期、航班編號、機型、出發時間、抵達時間、有無空位（可點「我要購票」= 有；帶「無可售機位」= 無）、備註。

- 輸出目錄：`tickets/`（不存在自動建立）
- 檔名：`立榮-{出發地點}-{抵達地點}-{年-月}.json`，例 `立榮-松山-金門-2026-10.json`
- 同月份查詢整併到同一檔：以「日期+航班編號」為鍵，同鍵以最新覆蓋，依日期/出發時間排序
- 驗證碼採重試迴圈（辨識偶有誤判、驗證碼有時間效期），每輪重載頁面重填表單再解碼；`--captcha-tries` 控制次數（預設 6）


## 第三部分：日期範圍抓取（--end-date）
加上 `--end-date` 後，一次抓取「出發日期 ~ 結束日期」逐日的空位資訊：
```powershell
node uniair-search.js --dep 松山 --arr 金門 --date 2026-10-25 --end-date 2026-10-29 --pax 2
```
- 第一天由搜尋頁進入；之後的天數在搜尋結果頁「上方日期列」點選該日取得空位。
- 日期列是 7 天滾動窗，目標日不在視窗內時會自動點最右邊那天讓視窗右滑，逐日推進。
- 點日期後會等「日期列 current 變成該日且航班清單已渲染」才抓取，避免 postback 導航競態。
- 跨月會自動分檔：例如 `--date 2026-10-29 --end-date 2026-11-02` 會同時寫入
  `立榮-松山-金門-2026-10.json` 與 `立榮-松山-金門-2026-11.json`，同月份整併。

## 第四部分：票種價格採集（uniair-fares.js）
「有空位」只代表可購票，實際票價要點「我要購票」後由伺服器的票種彈窗（`#FareModal`）才拿得到。
`uniair-fares.js` 沿用 uniair-search.js 的搜尋/驗證碼/日期列流程，逐日逐班：
點「我要購票」→ 等票種彈窗 → 解析票種與票價 → 按「取消」關彈窗（站台設計只 Hide modal，不會 postback，所以逐班很快）→ 續下一班。

```powershell
node uniair-fares.js --dep 松山 --arr 澎湖 --date 2026-10-25 --end 2026-10-27 --pax 4
```
選項：
- `--date` / `--end`：起訖日期（省略 `--end` 就只跑當天）
- `--pax`：人數（預設 4，影響彈窗可選人數上限）
- `--max-flights`：單日最多採集幾班（預設 99）
- `--no-save`：只印結果不寫檔
- `--captcha` / `--captcha-tries` / `--headless`：同 uniair-search.js

票種彈窗分「一般票種」與「居民票種」兩組，每筆票種記錄：
票種組、票種（全額/敬老/兒童/愛心/愛心陪同/縣府補助愛心陪同/居民…）、票價、幣別、
票種代碼（YU、YAFU…）、票種組碼、旅客類型、可選人數。

輸出：
- `tickets/立榮-{出發}-{抵達}-{年-月}.json`：航班記錄多 `票種` 陣列與 `票種最低票價`（沿用同一整併規則）
- `fares.json`：本次取得票價的航班（除錯用）
- `FlyTicket/澎湖航班.json` 新增 `票種價格` 區塊：以航線（例 `松山→澎湖`）分組，
  底下 `航班` 陣列以「日期+航班編號」為鍵整併，原有航線目錄鍵值不動。

## 第五部分：航線級票種價格（uniair-route-fares.js）
「有空位」只代表可購票，實際票價要點「我要購票」後由票種彈窗（`#FareModal`）才拿得到。
第四部分是**逐班**採集；本腳本是**航線級**：立榮同一條航線的一般票種票價與日期無關，
所以只要在一條航線上找到「第一班有空位的航班」，把它的五種票價當成整條航線的票價群，
寫進 `FlyTicket/澎湖航班.json` 該航線條目的 `票種價格`。

```powershell
node uniair-route-fares.js --pax 4
```
選項：
- `--date`：起算日（預設今天 +3 天，太近的日期常已售罄）
- `--try-days`：某條航線查不到有票航班時，往後連找幾天（預設 7）
- `--only 嘉義`：只跑「航線名稱含此字串」的航線，逐條補漏用
- `--pax`：人數（預設 4）
- `--force`：已有票價的航線也重跑（預設**自動略過**已有 `全額` 的航線）
- `--captcha 483021`：手動指定驗證碼，跳過模型

寫入格式（每條航線一組，與日期無關）：
```json
"票種價格": {
  "全額": 2197, "敬老": 1099, "兒童": 1978, "愛心": 1099, "愛心陪同": 1099,
  "範例航班": "B7-8609", "範例日期": "2026-10-25", "更新時間": "2026-10-20 22:20:36"
}
```
查不到票時寫 `"說明": "尚無取得票價"`（保留欄位，前端讀取形狀一致）。
頂層另有 `票種價格說明` 與 `票種價格更新時間`。

寫入安全：每條航線寫檔前會**重讀整份 `澎湖航班.json`**、只改自己那條航線，
因此與華信腳本（`Mandarin/mandarin-route-fares.js`）同時使用也不會互蓋。

逐日策略：每天都重新從搜尋頁進入（無航班航線的結果頁日期列不可靠），
驗證碼走重試迴圈（`captchaTries: 8`）；彈窗解析失敗會關窗續下一班。

已知狀況：
- 金門往返澎湖的航線很少開航，已自 `FlyTicket/澎湖航班.json` 移除，不再採集票價
- 立榮腳本**不可加 `--headless`**（見開頭警告）
